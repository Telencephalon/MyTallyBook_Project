## 用户确认范围

取消账本的 10 人上限，继续通过有效邀请加入。每个账号的流水以已有 `book_entry.created_by` 隔离，历史账单仍归原创建账号。用户明确选择共用所有者维护的分类、资金账户字典，不创建每人一套字典或复制历史账单。

筛选“创建人”指登录账号，与账单手填“人名”字段不同。OWNER 在首页最近账单、明细和统计页可选择全部成员或某个创建人；三个页面各自保存当前筛选，明细和每日趋势切换时回到第一页。已离开的历史创建人仍可被所有者筛选。

## 权限与接口

| 内容 | OWNER | ADMIN / MEMBER |
| --- | --- | --- |
| 流水列表、数量、详情和最近账单 | 全部或指定创建人 | 仅自己创建 |
| 月/自定义/全部范围的汇总、趋势、分类、账户和成员统计 | 全部或指定创建人 | 仅自己创建；日期范围和分页数量也隔离 |
| 编辑/删除流水 | 可处理全部 | 仅自己创建 |
| 分类和账户字典 | 可读写 | 只读并用于记账选择 |
| 账户余额 | 共享初始余额加全部流水净额 | 初始余额返回 0；当前余额仅个人流水净额 |
| 成员和邀请管理 | 保留原所有者权限 | 保留原成员/管理员权限；不能因此查看他人流水 |

服务端按数据库中的当前成员角色授权，旧令牌中的 OWNER/ADMIN 不扩大权限。非所有者伪造其他 `createdBy` 返回拒绝；访问他人详情返回不存在。所有 SQL 创建人条件使用参数绑定。幂等请求只对原创建人返回记录，不向其他账号透露记录的删除状态。

- `GET /api/v1/entries` 保留 `createdBy`；列表与总数强制同一范围。
- 五个统计 GET 接口新增可选正整数 `createdBy`；OWNER 不传表示全部，非 OWNER 不传表示本人，非 OWNER 传其他人会被拒绝。
- 账本和成员列表响应的 `maxMembers` 为 `null`，表示人数不限。新小程序同时兼容历史正整数响应与新空值合同，页面按新规则展示不限人数。
- 邀请仍验证到期时间、单次使用、成员/用户状态与唯一所有者，保留原事务锁。初始化仍受一次性口令保护，没有开放注册入口。

## 历史数据与发布兼容

本轮不新增数据库迁移，不修改历史 Flyway 文件。`max_users`、`max_members` 保留为历史元数据，不再决定接口返回或加入资格。数据库已有 `(ledger_id, created_by, entry_date)` 索引继续供个人流水查询使用。
