# 本地二次启动与启动包恢复记录

日期：2026-09-12。开发、测试、构建和启动均在主目录进行。

## 原因

此前在后端占用 JAR 时执行 Maven package，Spring Boot repackage 报无法重命名文件。现场启动包只有 272,222 字节，为未完成重新封装的普通 JAR。实际只读预检返回 `JarMigrationInventoryRejected`。关闭原服务后，再启动会在预检失败，而一键入口此前只等待健康检查超时，未提前指出启动包问题。

## 修改

- 一键启动在新开 SSH/后端窗口之前校验完整启动包，包括已批准迁移、Spring Boot 启动器、应用类及依赖目录。
- 源迁移校验独立于 JAR。源文件变化仍会拒绝启动，不通过自动构建绕过校验。
- 后端未运行且启动包缺失或不完整时，预检构建依赖，备份现有文件，再离线构建一次并重新验证。构建前再次检查本项目 Java 是否存在，避免覆盖运行中的 JAR。
- `-UpdateBackend` 也允许修复不完整的旧包；仍保留备份、进程身份验证和停止后再构建的顺序。
- 本地后端入口对常见预检失败给出固定原因和处理提示，不输出原始异常或凭据。

## 使用

日常启动：双击主目录 `Start-Dev.cmd`。已有健康后端/SSH 会复用。

更新代码并重新打包运行：在主目录执行 `./Start-Dev.cmd -UpdateBackend`。不要在 Java 占用运行包时直接执行 Maven package。

主启动结果窗口可以关闭；SSH 与后端服务窗口需要保留。关闭后端窗口后重新执行一键启动，会重新启动后端。关闭 SSH 窗口后，数据库隧道会断开；下次恢复隧道时重新输入 SSH 密码是正常认证流程。现有本机加密的数据库及微信配置继续复用。
