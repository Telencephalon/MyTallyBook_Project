> 版本：V2.0

> 实施边界：微信原生小程序 + Spring Boot + MySQL + Nginx + systemd；不使用 Docker、Redis、微服务和消息队列。

## 1. 方案结论

本项目面向一个固定家庭或小团队，最多允许 10 名活跃用户共同使用一个共享账本。第一版只实现：

- 微信登录、退出和登录态续用。
- 一次性初始化口令创建首位所有者。
- 所有者、管理员、普通成员三级权限。
- 限时、单次邀请加入和成员管理。
- 收入、支出、分类、资金账户和账单明细。
- 按月份、分类、账户和账单创建人统计。
- Ubuntu 单机原生部署、HTTPS、备份、恢复和发布。

第一版明确不实现：

- 多账本。
- 账户间转账和预算。
- CSV 导入导出。
- 图片凭证、OCR 和对象存储。
- 周期账单和消息提醒。
- 微信支付、银行卡或第三方账单自动同步。
- 第三方管理后台。
- Redis、Docker、微服务、消息队列和 Kubernetes。

## 3. 总体架构

```text
微信原生 TypeScript 小程序
        │ HTTPS /api/v1
        ▼
Nginx :443
        │ 反向代理
        ▼
Spring Boot :7631（生产环境仅监听 127.0.0.1）
        │ JDBC
        ▼
MySQL 8 :3306（仅监听 127.0.0.1）

Spring Boot ──HTTPS──► 微信 code2Session
```

组件职责：

| 组件 | 负责 | 不负责 |
|---|---|---|
| 微信小程序 | 页面、交互、令牌保存、API 调用 | 不保存 AppSecret，不做最终权限判断 |
| Nginx | HTTPS、反向代理、基础限流、请求大小限制 | 不处理业务数据 |
| Spring Boot | 登录、权限、事务、业务、审计和统计 | 不直接暴露公网端口 |
| MySQL | 用户、会话、账单、幂等、邀请和审计数据 | 不对公网开放 |
| systemd | 启停、自恢复和开机启动 | 不负责构建 JAR |

不使用 Redis 时：

| 常见需求 | 本项目实现 |
|---|---|
| 登录态 | `auth_session` 表保存令牌摘要 |
| 主动下线 | 更新会话撤销时间 |
| 防重复提交 | `client_request_id` 唯一索引 |
| 邀请码 | 数据库保存邀请令牌摘要和有效期 |
| 登录限流 | Nginx 限流 + 后端失败校验 |
| 统计缓存 | 直接查询具有正确索引的 MySQL |
| 并发控制 | 事务、行锁、唯一约束和乐观锁 |

## 5. 固定账本、用户与权限

### 5.1 固定账本

- 系统初始化时创建唯一共享账本。
- 后端不提供创建第二个账本的接口。
- 小程序不展示账本切换或新建入口。
- 数据库增加单账本约束，避免通过绕过接口插入第二条有效账本。
- 所有者也计入最多 10 名活跃成员。
- 被移除或已退出成员不占用活跃名额，历史账单继续保留。

### 5.2 权限矩阵

| 操作 | 所有者 | 管理员 | 普通成员 |
|---|:---:|:---:|:---:|
| 查看账单和统计 | 是 | 是 | 是 |
| 新增账单 | 是 | 是 | 是 |
| 修改、删除自己的账单 | 是 | 是 | 是 |
| 修改、删除他人的账单 | 是 | 是 | 否 |
| 管理分类和资金账户 | 是 | 是 | 否 |
| 创建、撤销邀请 | 是 | 是 | 否 |
| 移除普通成员 | 是 | 是 | 否 |
| 任免管理员 | 是 | 否 | 否 |
| 修改账本基本信息 | 是 | 否 | 否 |
| 转让所有者 | 是 | 否 | 否 |

所有权限必须由后端校验。前端隐藏按钮只用于改善体验，不能替代安全控制。

补充规则：

- 所有者不能直接退出，必须先转让所有权。
- 管理员不能移除所有者或其他管理员。
- 成员被移除或停用时，全部会话立即撤销。
- 普通成员只能修改、删除自己创建的账单。
- 账单、角色、成员和邀请的关键变更写入审计日志。

## 6. 微信登录、初始化和邀请

### 6.1 已注册用户登录

```text
小程序调用 wx.login()
  → 获得一次性 code
  → POST /api/v1/auth/wechat/login
  → Spring Boot 调用 code2Session
  → 获得 openid
  → 查询有效用户和成员关系
  → 签发应用会话令牌
```

会话规则：

- 微信 `code` 只发送到后端。
- 微信 `code` 有效期短且只能使用一次；后端收到后应立即兑换，不能保存后重复使用。
- `session_key` 不返回小程序、不写日志。
- AppSecret 只存在于服务器环境变量。
- 后端生成至少 32 字节的安全随机令牌。
- 数据库只保存令牌的 SHA-256 摘要。
- 小程序通过 `Authorization: Bearer <token>` 调用业务接口。
- 会话默认有效期 30 天。
- 退出、停用或移除成员时立即撤销会话。

### 6.2 首位所有者初始化

1. 部署时配置一次性 `APP_BOOTSTRAP_KEY`。
2. 首位用户进入小程序并执行微信登录。
3. 后端返回 `NEED_BOOTSTRAP`。
4. 小程序显示初始化页，用户输入初始化口令。
5. 小程序重新调用 `wx.login()`，把新 code 和口令提交到 `/api/v1/auth/bootstrap`。
6. 后端在一个事务中锁定 `app_config`，再次确认尚未初始化。
7. 后端校验口令，创建用户、唯一账本、OWNER 成员关系和默认基础数据。
8. 后端设置 `initialized=true` 并签发会话令牌。
9. 初始化口令从此失效，并从服务器环境文件中删除后重启服务。

事务锁与单例约束必须保证并发请求也只能产生一个所有者。

### 6.3 邀请加入

- 所有者或管理员创建默认 24 小时、最多 7 天有效的单次邀请。
- 服务端只保存邀请令牌摘要，原始令牌只在创建时返回一次。
- 小程序通过 `onShareAppMessage` 分享带邀请参数的小程序卡片，也可复制邀请码。
- 新用户打开邀请页后执行微信登录并提交 code 与邀请令牌。
- 后端在一个事务中锁定邀请和固定账本，检查状态、期限、使用次数和活跃人数。
- 成功后创建或重新启用用户和成员关系，将邀请标记为已使用并返回会话令牌。
- 并发接受最后一个名额时只能有一个请求成功。

登录返回的业务状态至少包括：

```text
AUTHENTICATED
NEED_BOOTSTRAP
INVITE_REQUIRED
USER_DISABLED
```

### 7.4 请求层

统一请求层负责：

- 开发、体验和生产 API 地址。
- Bearer Token。
- 请求 ID。
- 统一响应和业务错误码。
- 无论 `wx.request` 进入 `success` 还是 `fail`，都正确检查 HTTP `statusCode`；收到 4xx/5xx 不能当作业务成功。
- 超时与网络错误提示。
- 401 时清理会话并最多自动重新登录一次。
- 写操作防重复点击。
- 不对未知结果的写请求进行盲目自动重试。

小程序生成 UUID `clientRequestId`，后端用唯一索引确保新增账单幂等。

HTTP 链路的 `X-Request-Id` 与业务幂等键 `clientRequestId` 是两个不同概念。后端只接受由英文字母、数字、点、下划线和连字符组成的 1～64 位 `X-Request-Id`；缺失或不合法时生成 UUID，并把最终值同时写入 MDC、响应头和响应体。

### 8.4 账单规则

- Java 金额使用 `BigDecimal`，MySQL 使用 `DECIMAL(15,2)`。
- 金额始终大于 0，由 `INCOME` 或 `EXPENSE` 表示方向。
- 分类类型必须与账单类型一致。
- 分类和账户必须属于固定共享账本且处于可用状态。
- 创建人由后端认证上下文决定，前端不能指定。
- 成员统计按 `created_by` 聚合。
- 更新和删除携带 `version`，冲突返回 HTTP 409。
- 删除采用软删除。
- 新增使用 `clientRequestId` 保证幂等。
- 已被引用的分类和账户只能停用，不能物理删除。

## 9. MySQL 数据模型

数据库名称统一使用 `account_book`，字符集使用 `utf8mb4`，排序规则使用 `utf8mb4_0900_ai_ci`。不要使用 MySQL 的旧 `utf8`/`utf8mb3` 保存微信昵称。

### 9.1 核心表

| 表 | 用途 | 关键约束 |
|---|---|---|
| `app_config` | 初始化状态和人数上限 | 单例记录，最大值为 10 |
| `app_user` | 微信用户 | `openid` 唯一 |
| `auth_session` | 可撤销会话 | 令牌摘要唯一、带过期时间 |
| `ledger` | 唯一共享账本 | 单账本约束 |
| `ledger_member` | 成员和角色 | 同一用户关系唯一 |
| `ledger_invite` | 单次邀请 | 摘要唯一、过期、撤销和使用状态 |
| `category` | 收支分类 | 同类型名称唯一 |
| `fund_account` | 资金账户 | 同账本名称唯一 |
| `book_entry` | 收支明细 | 幂等、软删除、乐观锁 |
| `audit_log` | 关键操作审计 | 只追加 |

关系：

```text
app_user
  ├─< auth_session
  ├─< ledger_member >─ ledger
  ├─< book_entry.created_by
  └─< audit_log

ledger
  ├─< ledger_invite
  ├─< category
  ├─< fund_account
  └─< book_entry
```

### 9.2 `book_entry` 目标字段

```text
id                 BIGINT UNSIGNED
ledger_id          BIGINT UNSIGNED
entry_type         VARCHAR(16)
amount             DECIMAL(15,2)
category_id        BIGINT UNSIGNED
account_id         BIGINT UNSIGNED
entry_date         DATE
note               VARCHAR(500)
client_request_id  CHAR(36)
created_by         BIGINT UNSIGNED
updated_by         BIGINT UNSIGNED
created_at         DATETIME(3)
updated_at         DATETIME(3)
deleted_at         DATETIME(3)
version            INT UNSIGNED
```

索引至少包括：

```text
UNIQUE (ledger_id, client_request_id)
INDEX  (ledger_id, entry_date, id)
INDEX  (ledger_id, category_id, entry_date)
INDEX  (ledger_id, account_id, entry_date)
INDEX  (ledger_id, created_by, entry_date)
```

账户当前余额按“初始余额 + 收入 - 支出”计算，不额外维护易失真的冗余余额字段。

```text
餐饮、交通、购物、居住、医疗、教育、娱乐、人情、其他
```

收入分类：

```text
工资、奖金、理财、红包、退款、其他
```

资金账户：

### 9.4 Flyway V1 → V2 对齐结果

2026-09-04 已确认 `account_book_dev.flyway_schema_history` 中原始 V1 成功，版本为 `1`、脚本为 `V1__init_schema.sql`。因此 V1 从此保持不可变；此前“直接修订 V1”的判断由实际数据库证据正式替代。禁止修改 V1，也禁止使用 `flyway repair` 掩盖校验和差异。

目标结构由 `V2__align_approved_design.sql` 增量完成：

1. `ledger` 增加固定值唯一单例键，在保留已被外键引用的原 V1 主键结构时确保全库最多只有一条账本记录；应用初始化仍显式使用固定账本 ID `1`。
2. `book_entry` 删除 `member_id`，成员统计统一按 `created_by`，索引调整为 `(ledger_id, created_by, entry_date)`。
3. 邀请固定为单次使用，增加 `used_by` 和 `used_at`。
4. 邀请状态限制为 `ACTIVE`、`USED`、`REVOKED`、`EXPIRED`，并约束使用状态与使用人、使用时间一致。
5. `audit_log.request_id` 调整为 `VARCHAR(64)`，与后端接受的安全 `X-Request-Id` 长度一致。
6. V2 在结构变更前检查旧账本和邀请数据；存在多个账本、非标准固定账本 ID、已使用次数或无法无损映射的旧邀请状态时主动失败，必须先确认数据迁移规则。
7. 新数据库顺序执行原始 V1、V2；现有开发库只追加执行 V2。

固定 `account_book_test` 与专用 `account_book_test_app` 账号用于真实 MySQL 升级测试。测试只能通过 `127.0.0.1:13306` SSH 隧道连接，并且仅在 `DB_TEST_RESET_ALLOWED=account_book_test` 时由 Flyway 清理该 schema 内对象；测试程序不得删除数据库、不得使用 root、不得触碰开发库或生产库。

10 人并发上限和所有权转让仍属于后端事务规则，将分别在成员模块和所有权转让模块中通过并发集成测试实现。Hibernate 固定使用 `ddl-auto=validate`；生产数据库仍禁止手工改表。

## 10. 开发、测试与生产隔离

建议使用三个数据库：

```text
account_book_dev
account_book_test
account_book
```

分别使用独立账号和密码。生产账号只允许 `127.0.0.1` 连接，所有 MySQL 账号都不使用 root 运行应用。

本地通过 SSH 隧道连接开发库：

```powershell
$SshUser = Read-Host '请输入 SSH 用户，例如 root 或 ubuntu'
$SshPort = Read-Host '请输入实际 SSH 端口'
ssh -p $SshPort -N -L 13306:127.0.0.1:3306 "${SshUser}@117.72.101.42"
```

本地 JDBC 地址：

```text
jdbc:mysql://127.0.0.1:13306/account_book_dev
```

本地联调链路：

```text
微信开发者工具模拟器
  → http://127.0.0.1:7631
  → 本地 Spring Boot（统一使用 7631）
  → 127.0.0.1:13306
  → SSH 隧道
  → 京东云 account_book_dev
```

固定规则：

- 本地开发不得连接生产库。
- 自动测试只能使用专用账号清理固定 `account_book_test` 内的 schema 对象，不能删除数据库本身。
- 数据库测试必须显式设置 `DB_TEST_RESET_ALLOWED=account_book_test`，且只能经 `127.0.0.1:13306` SSH 隧道连接。
- 自动测试不得调用真实微信接口，应使用本地 Stub。
- 真机不能把 `127.0.0.1` 当作开发电脑，早期先使用模拟器；HTTPS 域名完成后再使用服务器进行真机联调。

## 11. 域名、备案与 HTTPS

两条路线并行：

```text
开发路线：小程序与后端本地开发
合规路线：小程序备案 + 域名 ICP 备案 + DNS + HTTPS
```

实施顺序：

1. 继续跟踪小程序备案的管局审核结果。
2. 确认域名已实名认证，且主体信息满足备案要求。
3. 通过京东云备案平台提交域名 ICP 备案。
4. 备案通过后创建 `api.<你的域名>` 的 A 记录，解析到 `117.72.101.42`。
5. 为 API 子域名申请受信任的 HTTPS 证书并配置完整证书链。
6. 在微信公众平台配置 request 合法域名 `https://api.<你的域名>`。
7. 关闭开发者工具的跳过域名校验选项。
8. 使用体验版和真机重新验证全部请求。

正式版不得：

- 使用 HTTP。
- 直接请求 IP 地址或 localhost。
- 把 AppSecret 放进小程序。
- 依赖“不校验合法域名”运行。

HTTPS 证书必须在有效期内、域名匹配、由系统受信任的证书机构签发且证书链完整，服务器至少支持 TLS 1.2。

小程序备案与 API 域名 ICP 备案是两个独立的发布条件：

```text
[ ] 小程序备案审核通过
[ ] API 域名 ICP 备案通过
```

## 12. Ubuntu 22.04 原生部署

### 12.1 目录和用户

```text
/etc/account-book/account-book.env

```

Java 应用使用专用系统用户 `accountbook` 运行，不使用 root，也不允许该用户通过密码登录。

### 12.2 组件

服务器安装：

- JDK 21 Runtime。
- Nginx。
- Certbot。
- MySQL Client。
- UFW。
- `curl`、`unzip` 等基础工具。

生产服务器不安装 IDEA、微信开发者工具或 Node.js，也不在生产机执行 Maven 构建。

### 12.3 systemd

服务名称统一为：

```text
account-book.service
```

核心规则：

- `User=accountbook`。
- 使用 `/etc/account-book/account-book.env` 注入敏感配置。
- Spring Boot 生产环境仅监听 `127.0.0.1:7631`。
- 启动失败自动重试。
- Flyway 失败时应用不得继续运行。
- 应用最大堆初始建议为 512 MB，最终按服务器实际内存压测后调整。

### 12.4 Nginx 和网络

请求链路：

```text
https://api.<域名>/api/v1/**
  → Nginx :443
  → http://127.0.0.1:7631/api/v1/**
```

Nginx 负责 443 上的 TLS、反向代理、登录接口限流、请求体限制、超时和访问日志。服务器 `*:80` 是既有 `/usr/weaver` Java/Resin 服务；MyTallyBook 不监听、不代理、不重定向、不修改该端口，也不用它签发证书。

MyTallyBook 仅新增京东云安全组和（仅当已启用时的）UFW 的 443 入站规则；既有 SSH 与 80 规则保持不变：

```text
443/tcp    # 小程序 API
```

不得为 MyTallyBook 新增或修改 80 规则，也不得对公网开放 `3306` 和 `7631`。若 UFW 为 inactive，本项目保持其 inactive，不设置默认策略或启用它；若已 active，只新增 443 规则且不删除、重排或改变其他规则。证书仅使用 DNS-01 或安全导入；备案前代理验证仅在服务器 `127.0.0.1:8081` 上进行，不访问 80。

### 12.5 发布和回滚

```text
本地 clean verify
  → 构建版本化 JAR
  → 计算 SHA-256
  → 上传 releases
  → 备份生产数据库
  → 切换 current
  → 重启 systemd
  → 检查健康接口和日志
  → 小程序生产冒烟测试
```

代码失败时切回上一版 JAR。数据库迁移使用向前修复策略，不自动执行破坏性降级。

### 12.6 备份

- 每日逻辑备份生产库。
- 保留最近 7 个日备份和 4 个周备份。
- 生成压缩文件和 SHA-256 校验值。
- 至少保留一份异机或私有对象存储副本。
- 每月恢复到临时数据库并核对表、行数和关键金额。

只有成功恢复过的备份才算有效备份。

## 14. 测试与错误处理

测试顺序：

```text
后端单元测试
  → MySQL 集成测试
  → API 权限测试
  → 小程序模拟器联调
  → 多人真机体验
  → 生产冒烟测试
```

必测场景：

1. 初始化口令只能成功一次，并发初始化只能产生一个所有者。
2. 第 10 名用户可以加入，第 11 名必须被拒绝。
3. 并发争夺最后一个名额时只能成功一个。
4. 未受邀请用户不能产生有效业务用户。
5. 普通成员不能修改或删除他人账单。
6. 管理员和所有者可以处理全部账单。
7. 双击新增只生成一条账单。
8. 同时编辑同一账单时，后提交者收到 HTTP 409。
9. 停用分类或账户后，历史账单仍可显示。
10. 软删除账单不再参与列表和统计。
11. 月初、月末、跨年和东八区日期统计正确。
12. 退出、停用和移除后，旧令牌立即无效。
13. AppSecret、微信 code、session_key 和完整令牌不出现在日志。
14. 公网不能访问 3306 和 7631。
15. 数据库备份可以恢复到临时库并通过数据核对。

错误处理：

| 场景 | 处理 |
|---|---|
| 网络中断 | 保留用户输入，允许手动重试 |
| 登录过期 | 清除旧令牌并重新执行微信登录 |
| 重复提交 | 根据 `clientRequestId` 返回原结果 |
| 乐观锁冲突 | 返回 409，提示刷新后重试 |
| 邀请失效 | 显示失效原因并要求重新邀请 |
| 人数已满 | 不创建残留用户或成员数据 |
| 无权限 | 返回 403，不伪装成网络错误 |
| 服务异常 | 页面展示 requestId，服务端据此查日志 |
| Flyway 失败 | 阻止应用启动 |
