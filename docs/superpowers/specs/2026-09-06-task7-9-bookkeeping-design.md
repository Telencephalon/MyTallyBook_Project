## 2. 已确认的业务原则

- 一个固定共享账本，`ledger_id=1`，币种 CNY，账本时区 Asia/Shanghai。
- 全体有效成员可查询分类/账户/账单/统计及新增账单。
- OWNER/ADMIN 管理分类、账户，并可修改/删除全部账单；MEMBER 仅可修改/删除自己创建的账单。权限由服务端最新成员状态核验。
- 分类及账户从未被账单引用时可物理删除；存在引用（包括软删除账单）则拒绝删除并提示停用。
- 用户本轮已明确确认：分类收入/支出类型、账户类型创建后固定；需要换类型时新建。名称、排序、启停仍可管理。
- 账户初始余额仅创建时填写，之后不可编辑；当前余额按初始余额 + 未删除收入 − 未删除支出计算。
- 新增账单 UUID 防重，更新/删除必须提交 version，账单删除采用软删除。
- 成员统计按账单 created_by，不按修改人或当前是否仍是有效成员计算。

## 3. 共用接口与数据规则

沿用 `ApiResponse`/`ApiError`、Bearer 身份和请求 ID。列表返回 `{items,page,pageSize,total}`；分页从 1 开始，默认每页 20，最大 50，拒绝非法参数。分类/账户作为小规模字典返回完整 items 列表并确定性排序。

ID 保持现有接口的 JSON 安全整数规则（正整数且不超过 JavaScript 安全整数上限），服务端不接受前端指定 ledgerId、createdBy、updatedBy 或角色。

金额以十进制字符串传输和返回，返回值固定两位小数；Java/SQL 全程 BigDecimal/DECIMAL，不用浮点数进行货币计算。输入不接受指数形式、不静默四舍五入；单笔金额大于 0，最多两位小数且不超 DECIMAL(15,2)。初始余额可以是零或负值，绝对值遵守同一字段精度。聚合金额允许超过单笔上限，仍返回字符串。

业务日期使用严格 `YYYY-MM-DD` 的真实日历日期，范围 1000-01-01 至 9999-12-31，与现有 MySQL DATE 一致；不增加原方案没有的“禁止未来日期”规则。默认日期按账本时区计算。首页“最近”按业务日期排序，因此未来日期也会按该规则出现，不等同于最后创建时间。

所有变更沿用 `LedgerWriteGuard` 的锁序，在同一事务内验证最新有效成员、管理权限、固定账本归属及资源状态；关键变更和审计一起提交，审计失败则事务回滚。审计不记录 Token、密码或账单备注全文。

读接口使用一致快照核验账本及有效成员，关联分类/账户/历史创建人时不加 ACTIVE 过滤以免丢失历史记录。小程序异步响应沿用页面生命周期、操作序号和 session revision 保护，不让旧身份/旧页面请求写回当前页面。

## 4. Task 7：分类与资金账户

### 4.1 资源及权限

分类字段：id、entryType、name、icon、color、sortNo、systemDefault、status。

账户字段：id、name、accountType、initialBalance、currentBalance、sortNo、status、version。账户类型为 CASH、WECHAT、BANK、ALIPAY、OTHER。

名称去除首尾空白后非空，最多 40 字符；唯一性遵循现有数据库索引和排序规则，分类在同账本同类型下唯一，账户在同账本唯一。停用记录仍占用其名称。排序号为 0～32767，同值按 id 升序；页面提供排序号编辑，不引入拖拽排序的新接口。

icon 可为空或受限图标标识，color 可为空或 `#RRGGBB`；不允许任意 HTML/脚本。默认数据只复用现有初始化结果，不重建；systemDefault 为展示来源标记，不赋予额外删除豁免或限制。

### 4.2 接口

- `GET/POST /api/v1/categories`
- `GET/PATCH/PUT /api/v1/categories/{categoryId}`
- `DELETE /api/v1/categories/{categoryId}`
- `GET/POST /api/v1/accounts`
- `GET/PATCH/PUT /api/v1/accounts/{accountId}`
- `DELETE /api/v1/accounts/{accountId}`

列表支持类型（分类）和 ACTIVE/DISABLED/全部状态筛选。普通成员可以查看全部以便历史账单展示，但不能新增/修改/排序/启停/删除。更新兼容原设计 PATCH，增加 PUT 供现有小程序请求层使用，两者接受同一完整可编辑字段 DTO。修改请求只允许列出的可编辑字段，拒绝更改类型及初始余额；账户修改和删除携带 version，过期则 409。分类沿用现有无 version 的 schema，在事务内串行提交，不声称具备基于版本的编辑冲突检测。

删除前检查所有账单引用；被引用返回明确 409 业务错误与“请停用”提示，不偷偷改成删除。停用及重新启用均保留 ID、名称、初始余额和历史引用。

### 4.3 页面

新增 category-list/category-edit/account-list/account-edit，主页或资料区域提供入口。列表具备加载/错误/空态、类型/状态筛选、排序、启停及删除确认。编辑页保留网络失败前的输入；成员只能查看。账户列表展示初始及当前余额，停用账户不凭空消失。

## 5. Task 8：收支记账

### 5.1 接口与展示

- `POST/GET /api/v1/entries`
- `GET /api/v1/entries/{entryId}`
- `PATCH/PUT /api/v1/entries/{entryId}`：两者采用相同完整编辑 DTO，客户端使用 PUT。
- `DELETE /api/v1/entries/{entryId}`：必须携带 version。
- `GET /api/v1/entries/creators`：返回有效成员及有历史账单的创建人，供筛选，包含 userId/displayName，不泄露 OpenID 等认证信息。

新增数据：entryType、amount、categoryId、accountId、entryDate、note、clientRequestId。修改使用相同业务字段和 version，不允许变更创建人及幂等键。备注最多 500 字符，可为空。

列表筛选：dateFrom/dateTo（界面均含边界）、entryType、categoryId、accountId、createdBy、keyword。SQL 用参数绑定；日期按闭开范围表达，最大日期边界用不溢出的比较；关键词只搜索备注且按字面文本处理 `%`、`_` 等字符。默认全日期范围，按 entry_date DESC、id DESC 排序。详情、列表均显示当前关联名称及分类/账户状态。

### 5.2 历史停用关联的编辑（本规格建议）

新增账单只能选择 ACTIVE 且属于本账本的分类与账户，分类类型必须匹配收入/支出方向。

旧账单引用后来停用的分类/账户时，允许保留未改变的原关联并修改金额、日期或备注；更换关联时新项必须 ACTIVE。若更改收支方向，必须改选 ACTIVE 且类型匹配的分类。编辑页标注原停用项，但不把停用项作为其他账单的新选项。

### 5.3 幂等与冲突（沿用现有 schema）

clientRequestId 为规范化小写 UUID，标识一次用户新增意图，与 X-Request-Id 独立。同一创建人重用同一 UUID 时只返回已有账单的当前状态，不覆盖内容、不产生第二条；这不是原始响应或原始表单快照。不同创建人使用相同键则返回 409，不将其当作本人的创建成功。

命中已软删除账单的 UUID 时返回明确已删除/幂等冲突，不复活、不插入第二条。当前 schema 没有原始请求指纹，因此不声称可以在账单已编辑后可靠比对原始提交内容。

前端每次用户新建意图生成一个 UUID；未知网络结果后保留原键与原表单供手动重试，不自动换键。若用户要放弃未知结果并另开一笔，先明确提示可能已保存、建议查询确认，不能静默重复提交。表单只在页面内存暂存，不新增持久化存储财务草稿。

修改、删除在数据库 WHERE 条件中同时校验 ledger_id、未删除和 version，成功递增 version 并写 updated_by。过期版本返回 409，页面保留用户输入并提示重新加载，不静默覆盖。已软删除记录的详情、更新及再次删除返回 404；列表、余额及统计排除它。

### 5.4 页面

新增 entry-create、entry-list、entry-detail、entry-edit；包含收入/支出选择、金额、分类、账户、日期和备注，完整筛选及分页。删除需要确认；普通成员没有他人账单编辑/删除入口，后端仍独立拒绝越权请求。

## 6. Task 9：首页与统计

五个 GET 接口沿用批准路径：

- `/api/v1/statistics/monthly-summary`
- `/api/v1/statistics/daily-trend`
- `/api/v1/statistics/categories`
- `/api/v1/statistics/accounts`
- `/api/v1/statistics/members`

统一接受 month=`YYYY-MM`，缺省为账本时区当前月；以 [月首,下月月首) 查询 entry_date。可选择月份为 1000-01 至 9999-12；最后一个合法月份只绑定下界，因为 DATE 数据域内不存在更晚的月份，不构造 MySQL 无法表示的 10000 年上界。五组均是所选月的账单流量，不把账户初始余额/当前余额计入月结余。

月汇总返回收入、支出、结余及笔数。每日趋势补齐选月全部日期（含零），按日期升序返回。分类和成员排行可切换收入/支出，默认支出，按金额降序、ID 升序；占比以当前类型合计为分母，空集返回 0.00 和空列表。账户统计并列显示该月收入、支出、净额及笔数，当前余额由 Task 7 页面展示。

历史名称取当前关联名称，成员优先使用非空 display_name，否则 nickname；已退出/被移除者有历史账单时仍参与统计。不新增历史名称快照，不把当前活跃成员列表当作历史成员全集。

首页替换功能占位，展示本月收入/支出/结余、全日期范围最近 5 条未删除账单，以及记一笔/明细/统计/字典管理入口；保留资料、成员、邀请和退出入口。最近 5 条复用 Task 8 列表接口，不新增重复后端接口。

统计页用原生卡片、日趋势金额列表/简易条形展示、排行榜和横向进度条，支持切换月份与收支方向。无数据、加载失败、身份失效分别呈现，不用 0 冒充失败后的统计结果。

## 7. 备选方式与取舍

推荐上述“沿用现有 schema、实时 SQL 聚合、按模块逐项交付”。它满足当前已确认范围，且不把数据库迁移放在开发路径前面。

不采用“先只做模拟页面再接后端”：容易出现页面可见但真实接口不存在的交接问题；各项一起交付页面和接口。

不采用“新增余额缓存表及请求快照表”：确实可支持额外性能/严格原始响应重放能力，但超出本轮明确需求，需要额外 schema 与迁移验收。本轮不声称具备这些能力。
