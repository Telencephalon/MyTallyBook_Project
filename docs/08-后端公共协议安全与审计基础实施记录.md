## 2. 统一响应协议

成功响应：

```json
{
  "code": "OK",
  "message": "success",
  "data": {},
  "requestId": "client-request-123",
  "timestamp": "2026-08-30T09:00:00Z"
}
```

失败响应：

```json
{
  "code": "VALIDATION_FAILED",
  "message": "请求参数不正确",
  "details": {
    "name": "名称不能为空"
  },
  "requestId": "client-request-123",
  "timestamp": "2026-08-30T09:00:00Z"
}
```

当前公共错误码：

| HTTP | `code` | 默认消息 |
|---:|---|---|
| 400 | `VALIDATION_FAILED` | 请求参数不正确 |
| 401 | `AUTHENTICATION_REQUIRED` | 请先登录 |
| 403 | `ACCESS_DENIED` | 没有操作权限 |
| 404 | `RESOURCE_NOT_FOUND` | 资源不存在 |
| 405 | `METHOD_NOT_ALLOWED` | 请求方法不受支持 |
| 409 | `CONFLICT` | 请求冲突 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | 请求内容类型不受支持 |
| 500 | `INTERNAL_ERROR` | 服务暂时不可用 |

前端必须按 HTTP 状态和稳定 `code` 分支，不得依赖中文 `message`。

## 3. 请求 ID 规则

请求头名称为 `X-Request-Id`。合法值必须满足：

```text
[A-Za-z0-9._-]{1,64}
```

缺失或不合法时由后端生成 UUID。最终请求 ID 会写入：

1. 当前请求属性。
2. SLF4J MDC 的 `requestId`。
3. HTTP 响应头 `X-Request-Id`。
4. 统一响应体的 `requestId`。

`audit_log.request_id` 使用 `VARCHAR(64)`，与此规则一致。请求追踪 ID 不等于新增账单的 `clientRequestId` 幂等键。

## 4. 认证与开放路径

无需 Bearer Token 的路径只有：

```text
GET/任意健康探测  /actuator/health 及其子路径
POST              /api/v1/auth/wechat/login
POST              /api/v1/auth/bootstrap
POST              /api/v1/auth/invites/accept
```

其余请求默认必须认证。业务方法可使用 `hasRole('OWNER')`、`hasAnyRole('OWNER','ADMIN')` 等方法级规则。当前用户对象包含 `userId`、固定账本 `ledgerId`、成员关系 `memberId` 和角色。

实际 Token 原文不得进入数据库、响应日志或审计详情。Task 4 必须实现“原文只返回一次、数据库只存摘要、退出或重新登录可撤销”的会话校验器。

## 5. 异常和日志边界

- 500 响应只返回 `INTERNAL_ERROR` 和固定通用消息。
- 全局异常日志只记录请求 ID、HTTP 方法、已匹配的安全路由模板和异常类型，不记录异常消息、请求体、认证头或完整栈，避免 SQL、Token 或密码随异常文本泄漏。
- Bearer Token 校验器异常同样返回稳定 500，并且不记录 Token。
- 审计详情会递归脱敏 `code`、`session_key`、`AppSecret`、各类 Token、secret 和 password 字段。

## 6. 审计服务使用约束

`AuditLogService.append` 使用 `Propagation.MANDATORY`，只能在已有业务事务中调用。这样业务写入失败时审计不会单独提交，业务写入成功时关键变更和审计同时提交。

审计表只允许插入，不提供修改和删除接口。调用方只写必要字段差异，不复制完整 Token、微信会话密钥、密码或敏感备注全文。

示意调用：

```java
auditLogService.append(new AuditLogService.AuditEvent(
        1L,
        currentUser.userId(),
        "ENTRY_CREATE",
        "BOOK_ENTRY",
        entryId,
        requestId,
        Map.of("amount", amount, "entryType", entryType)
));
```
