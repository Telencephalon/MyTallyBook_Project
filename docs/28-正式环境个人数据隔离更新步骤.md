## 3. 停服并备份

这一步需要 MySQL root 密码；它可能与 SSH 密码不同。不要把密码写在命令中或发到聊天里。备份失败时不进入安装步骤，先执行 `systemctl start account-book.service` 恢复原版本，再排查备份。

```bash
(
set -euo pipefail
umask 077
RECORD='/root/account-book-release-record-20260923-195353'
mkdir -m 0700 "$RECORD"
readlink -f /opt/account-book/current.jar > "$RECORD/previous-jar-path.txt"
sha256sum /opt/account-book/current.jar > "$RECORD/previous-jar.sha256"
cp -p /etc/account-book/account-book.env "$RECORD/account-book.env"
cp -p /etc/systemd/system/account-book.service "$RECORD/account-book.service"
if [ -d /etc/systemd/system/account-book.service.d ]; then
  cp -a /etc/systemd/system/account-book.service.d "$RECORD/"
fi
systemctl stop account-book.service
test "$(systemctl show account-book.service --property=MainPID --value)" = 0
install -d -m 0700 /var/backups/account-book
BACKUP_DIR=$(mktemp -d /var/backups/account-book/predeploy-20260923-195353-XXXXXX)
/opt/mysql8/bin/mysqldump \
  --protocol=SOCKET --socket=/opt/mysql8/run/mysql.sock \
  --user=root -p \
  --single-transaction --routines --triggers --events \
  --set-gtid-purged=OFF --no-tablespaces \
  --result-file="$BACKUP_DIR/account_book_dev.sql" account_book_dev
gzip "$BACKUP_DIR/account_book_dev.sql"
gzip -t "$BACKUP_DIR/account_book_dev.sql.gz"
sha256sum "$BACKUP_DIR/account_book_dev.sql.gz" > "$BACKUP_DIR/account_book_dev.sql.gz.sha256"
sha256sum -c "$BACKUP_DIR/account_book_dev.sql.gz.sha256"
printf '%s\n' "$BACKUP_DIR/account_book_dev.sql.gz" > "$RECORD/verified-backup-path.txt"
printf '备份成功：%s\n' "$BACKUP_DIR/account_book_dev.sql.gz"
)
```

记录目录中的环境文件含密钥，只保留在服务器，不截图或回传其内容。重复执行时目录已存在会中止；先核对现有记录，不直接删除重来。

## 4. 安装并启动新版

仅在上一块明确显示备份成功后执行。安装器使用 `--no-restart`，随后等待健康状态为 `UP`；保留所有旧 JAR，不覆盖 env、service、Nginx 或证书。

```bash
(
set -euo pipefail
RECORD='/root/account-book-release-record-20260923-195353'
cd /root/server-upload-20260923-195353
test -s "$RECORD/verified-backup-path.txt"
BACKUP_FILE=$(cat "$RECORD/verified-backup-path.txt")
sha256sum -c "$BACKUP_FILE.sha256"
sha256sum -c SHA256SUMS
test "$(systemctl show account-book.service --property=MainPID --value)" = 0
test ! -e /opt/account-book/releases/account-book-server-20260923-195353.jar
KEEP_COUNT=$(( $(find /opt/account-book/releases -maxdepth 1 -type f -name '*.jar' | wc -l) + 1 ))
bash ./install-release.sh \
  --artifact ./account-book-server-20260923-195353.jar \
  --sha256 ./SHA256SUMS --keep "$KEEP_COUNT" --no-restart
runuser -u accountbook -- test -r /opt/account-book/current.jar
systemctl start account-book.service
READY=0
DEADLINE=$((SECONDS + 120))
while (( SECONDS < DEADLINE )); do
  if HEALTH=$(curl -fsS --connect-timeout 2 --max-time 3 \
      http://127.0.0.1:7631/actuator/health 2>/dev/null); then
    if printf '%s' "$HEALTH" | grep -Eq '"status"[[:space:]]*:[[:space:]]*"UP"'; then
      READY=1
      break
    fi
  fi
  sleep 2
done
if [ "$READY" -ne 1 ]; then
  systemctl stop account-book.service
  echo '新版未就绪，已停止本项目后端。按下方回退步骤恢复旧版本。'
  exit 1
fi
readlink -f /opt/account-book/current.jar
sha256sum /opt/account-book/current.jar
systemctl is-active account-book.service
printf '%s\n' "$HEALTH"
)
```

成功时应看到新 JAR 路径、以 `a9b1a56c` 开头的完整摘要、`active` 和 `"status":"UP"`。这表示后端更新成功，不代表多账号业务验收已经通过。

## 新版启动失败时恢复旧后端

本次迁移文件与旧包一致，回退只切换 JAR，不恢复或覆盖数据库。以下动作会恢复旧包原来的权限行为，因此仍需后续排查新版启动失败。

```bash
(
set -euo pipefail
OLD='/opt/account-book/releases/account-book-server-20260920-131055.jar'
printf '%s  %s\n' \
  'a9a45841433e922c147a6a45a5b31ad05ce324cf3b35fb57313309d3b00866e9' \
  "$OLD" | sha256sum -c -
systemctl stop account-book.service
NEXT="/opt/account-book/.current-isolation-rollback.$$"
ln -s -- "$OLD" "$NEXT"
mv -fT -- "$NEXT" /opt/account-book/current.jar
systemctl start account-book.service
readlink -f /opt/account-book/current.jar
)
```

旧版启动后需等待并检查 `http://127.0.0.1:7631/actuator/health` 返回 `UP`。不要用重建数据库、Flyway clean/repair 或更换密钥处理启动失败。
