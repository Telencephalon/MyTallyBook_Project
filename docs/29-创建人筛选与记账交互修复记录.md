日期：2026-10-08。开发与测试目录：`D:/Work/Workplaces/privateWork/AAProject/MyTallyBook_Project`。

## 本轮确认的行为

1. 首页最近账单、明细和统计的所有者创建人筛选首次进入时默认本人，仍可选择其他在册成员或全部成员。三个页面分别保留手动选择；清除明细筛选恢复本人。ADMIN/MEMBER 不展示跨创建人选项，后端继续强制本人读取范围。
2. 编辑账单切换收入、支出时保留兼容的通用分类，否则优先恢复该方向之前选择的分类、同名分类或首个可用分类。回切可恢复原始停用分类，停用分类不会被带到另一收支方向。仅在目标方向没有可用分类时提示重新选择，不自动保存，也不增加切换请求。
3. 创建人选项只返回当前账本中成员状态和用户状态均为 ACTIVE 的成员。退出或移出的成员不再通过历史账单重新进入选项；已选人员离开时，刷新选项后回到本人并重新查询相同范围的数据。历史账单保留，所有者选择全部仍可查看。
4. 人情快捷入口默认收入；生活快捷入口默认支出。普通新增保持默认支出。生活人名仍默认当前创建人的显示名或昵称。
5. 明细筛选卡片增加常显的“输入人名搜索”快捷条件；按查询按钮或键盘搜索键执行。支持部分姓名匹配、去除首尾空格，与日期、分类、收支、资金账户、创建人及备注组合使用。输入过程不逐字发送请求，加载中重复确认不会重复查询。查询回到第一页，翻页保留人名，清除筛选同时清空人名和备注。

本轮替代早期“所有者默认全部”“已离开的历史创建人仍出现在筛选选项”和“编辑切换收支直接清空分类”的行为。分类与账户字典仍共用，由所有者维护。

## 查询合同与缓存

- `GET /api/v1/entries` 新增可选 `personName`，最多 64 个 Unicode 码点，空白视为不限。服务端使用参数化的 `person_name LIKE` 部分匹配，`%`、`_`、反斜杠按字面字符处理。
- 人名是账单手填字段，不是创建账号。原有 `DataScope` 仍按数据库当前成员角色和 userId 授权，`withCreator` 保留人名及其他查询条件，列表和总数采用同一谓词并在分页前筛选。
- OWNER 的接口未指定 `createdBy` 时继续代表全部，客户端用本人 userId 实现默认本人；非所有者即使不传创建人也强制本人，不能通过人名查询绕过隔离。
- 人名加入明细快照查询标识，不会复用另一个人名条件的结果。保留原有 15 秒 tab 快照有效期、角色与会话身份隔离；成员移出等写请求仍通过 HTTP 层使快照失效。
- 首页、明细、统计的创建人控件选中索引与显示名称同步；异步加载沿用原生命周期和操作序号保护。
