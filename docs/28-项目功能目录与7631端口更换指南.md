```text
├─ predeploy-<时间>/                       # 已执行的发布前备份记录
```

应用标准输出/错误输出由 journald 接收，用 `journalctl -u account-book.service` 查看；代码没有要求 `/opt/account-book/logs/app.log` 必须存在。

仓库的 systemd 模板仍使用 `After=... mysql.service`、`ExecStart=/usr/bin/java ...`；第26号记录的首发安装包已调整为 `mysql8.service` 和 `/usr/lib/jvm/java-21-openjdk-amd64/bin/java`。**不要用仓库原模板直接覆盖服务器 unit，否则可能丢失这两项部署修正。**

## 6. MySQL 目录与数据库

### 6.1 已知的服务器目录

```text
/opt/mysql8/                               # 已有 MySQL8 安装目录
├─ bin/
│  ├─ mysql                                # 客户端：登录、执行SQL、查询配置
│  ├─ mysqldump                            # 逻辑备份客户端
│  └─ mysqld                               # 服务进程二进制；实际路径以 mysql8.service ExecStart 核对
├─ my.cnf                                  # 第07号历史记录确认的配置文件，当前加载情况需复核
└─ run/
   └─ mysql.sock                           # 已记录的本机 socket 连接入口

<SELECT @@datadir 返回的目录>/              # 数据文件实际目录，本轮没有证据确定其绝对路径
├─ account_book_dev/                       # 通常存放业务库表空间；实际布局受存储设置影响
├─ mysql/                                 # MySQL 系统数据
└─ 其他 InnoDB / redo / undo 等文件         # 由数据库管理，不按源码方式直接修改或复制恢复

<@@log_error 返回的位置>                    # 错误日志；可能另由服务日志收集
<@@pid_file 返回的位置>                     # mysqld PID文件
<@@log_bin_basename 返回的位置>             # binlog前缀；仅启用时有对应日志文件

```

不要把通用教程中的 `/var/lib/mysql` 或 `/etc/mysql/mysql.conf.d/mysqld.cnf` 当作这台机器已确认的位置；安装目录和数据目录也不必相同。

### 6.2 一次性查清真实物理路径的只读命令

以后在服务器 Bash 执行，登录密码在终端提示中输入，不写进命令。若现有管理账号使用 socket 免密认证，可沿用已验证方式。

```bash
systemctl show mysql8.service -p FragmentPath -p DropInPaths -p ExecStart
ls -ld /opt/mysql8 /opt/mysql8/bin /opt/mysql8/run
ls -l /opt/mysql8/my.cnf /opt/mysql8/run/mysql.sock
/opt/mysql8/bin/mysql --protocol=SOCKET --socket=/opt/mysql8/run/mysql.sock -u root -p
```

进入 MySQL 后：

```sql
SELECT @@version, @@basedir, @@datadir, @@port, @@socket,
       @@pid_file, @@log_error, @@log_bin, @@log_bin_basename;
SELECT VARIABLE_NAME, VARIABLE_SOURCE, VARIABLE_PATH
FROM performance_schema.variables_info
WHERE VARIABLE_NAME IN ('basedir','datadir','port','socket','pid_file','log_error');
SHOW FULL TABLES FROM account_book_dev;
SELECT installed_rank, version, description, success
FROM account_book_dev.flyway_schema_history
ORDER BY installed_rank;
```

`VARIABLE_PATH` 在配置来自文件时可帮助识别来源；为空不等于没有配置，还要看 `VARIABLE_SOURCE` 和服务启动参数。`datadir` 的定义见 [MySQL 官方系统变量文档](https://dev.mysql.com/doc/refman/8.0/en/server-system-variables.html#sysvar_datadir)。

## 9. 生产服务器：7631 改成 17631 的操作步骤

`17631` 只是本文示例。实际操作先选择未占用端口，并在本文各处一致替换。本轮只写说明，没有执行这些命令。下面在**服务器 root 的同一个 Bash 会话**中按9.1～9.5顺序逐段执行，保留端口及备份目录变量；普通账号先进入授权管理会话。若退出终端，先根据备份记录恢复变量，不直接从中间复制执行。单实例服务重启和代理切换会有短暂不可用，安排维护时段。

### 9.1 先确定真正生效的配置

后端两份 `application*.yml` 都使用 `port: ${SERVER_PORT:7631}`。当前 unit 通过 `EnvironmentFile=/etc/account-book/account-book.env` 加载环境文件，模板 env 也已经包含 `SERVER_PORT=7631`。

**环境文件中的同名值会覆盖 unit 的 `Environment=` 值。** 所以只在 unit/drop-in 写 `Environment=SERVER_PORT=17631`，而环境文件仍为7631，可能仍启动旧端口。使用 env 作为这台服务器端口的配置来源；若另有 `--server.port=` 启动参数或后读的环境文件，应先消除冲突。依据：[systemd v249 官方说明](https://github.com/systemd/systemd/blob/v249/man/systemd.exec.xml)。

```bash
set -Eeuo pipefail
OLD_PORT=7631
NEW_PORT=17631

command -v python3 >/dev/null || { printf '健康JSON检查需要python3，请先确认工具后再操作\n' >&2; exit 1; }
systemctl is-active account-book.service
systemctl show account-book.service -p FragmentPath -p DropInPaths -p ExecStart -p EnvironmentFiles
grep -nE '^SERVER_(ADDRESS|PORT)=' /etc/account-book/account-book.env
grep -n 'proxy_pass' /etc/nginx/snippets/account-book-proxy.inc
readlink -f /etc/nginx/sites-enabled/account-book.conf
ss -lntp "sport = :$OLD_PORT"

if [ -n "$(ss -H -lnt "sport = :$NEW_PORT")" ]; then
  printf '新端口已被占用，停止操作\n' >&2
  exit 1
fi
curl -fsS --connect-timeout 2 --max-time 5 "http://127.0.0.1:$OLD_PORT/actuator/health"
```

旧健康应为 `UP`，旧监听应属于本项目Java。若发现同名覆盖文件、不同代理路径或新端口占用，先按实际配置调整方案，不继续套用下面命令。

### 9.2 备份将修改的配置

```bash

: "${NEW_PORT:?请先在同一会话执行9.1}"
```

记录最后打印的目录。里面包含秘密环境文件，目录保持root独占，不下载到普通文档目录、不提交Git。此操作不改数据结构，配置回退不需要恢复数据库。

### 9.3 修改后端环境文件与 Nginx 代理片段

```bash
nano /etc/account-book/account-book.env
```

只将端口改为目标值，地址保持回环；保留数据库、微信与原有密钥等其余项：

```ini

```

确保只有一个有效的 `SERVER_PORT=` 定义。不要用 `source account-book.env` 加载文件，它按 systemd 环境文件语法使用。保持 `root:root`、`0600` 权限。

```bash
nano /etc/nginx/snippets/account-book-proxy.inc
```

只改代理端口：

```nginx
proxy_pass http://127.0.0.1:17631;
```

保留该行末尾的分号，**不要添加端口后的 `/`**；现有 `/api/v1/` 路径需要完整传给后端。`proxy_pass` 带URI与不带URI的行为不同，见 [Nginx 官方文档](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_pass)。

```bash
grep -nE '^SERVER_(ADDRESS|PORT)=' /etc/account-book/account-book.env
grep -n 'proxy_pass' /etc/nginx/snippets/account-book-proxy.inc
nginx -t
```

此时只验证磁盘上的 Nginx 新配置，**还未 reload**。所有API location引用同一个片段，通常不需要逐条改站点文件。若现场站点有内联 `proxy_pass`，应在9.1核对阶段找到并纳入备份/变更范围。

### 9.4 重启后端，等新端口健康后再切换代理

```bash
: "${OLD_PORT:?请先恢复9.1中的原端口变量}"
: "${NEW_PORT:?请先恢复9.1中的新端口变量}"
: "${PORT_BACKUP:?请先完成9.2备份并记录目录}"
if ! systemctl restart account-book.service; then
  printf '后端重启失败，不要reload Nginx；按9.6回退，备份目录：%s\n' "$PORT_BACKUP" >&2
  exit 1
fi

health_ok=0
health_deadline=$((SECONDS + 120))
while (( SECONDS < health_deadline )); do
  if curl -fsS --connect-timeout 2 --max-time 5 \
       "http://127.0.0.1:$NEW_PORT/actuator/health" 2>/dev/null \
       | python3 -c 'import json,sys; sys.exit(0 if json.load(sys.stdin).get("status") == "UP" else 1)' 2>/dev/null; then
    health_ok=1
    break
  fi
  sleep 2
done
if [ "$health_ok" -ne 1 ]; then
  printf '新端口未健康，不要reload Nginx；按9.6回退\n' >&2
  exit 1
fi

systemctl is-active account-book.service
ss -lntp "sport = :$NEW_PORT"
ss -lntp "sport = :$OLD_PORT"
nginx -t
systemctl reload nginx
systemctl is-active nginx
```

检查新监听确实是本项目Java、地址仍是回环；旧端口应不再由本项目监听。上述只改 env 内容，无需 `daemon-reload`，重启会重新读取 env。**若额外修改了 unit/drop-in，则必须在 restart 前执行 `systemctl daemon-reload`。** 不需要重新打JAR、不需要重启MySQL。

### 9.5 验证代理链路和手机

在服务器验证：

```bash
curl -fsS --connect-timeout 2 --max-time 5 "http://127.0.0.1:$NEW_PORT/actuator/health"
curl -sS -i --connect-timeout 3 --max-time 10 --resolve www.cr-chenny.com:443:127.0.0.1 https://www.cr-chenny.com/api/v1/users/me
curl -sS -i --connect-timeout 3 --max-time 10 --resolve www.cr-chenny.com:443:127.0.0.1 https://www.cr-chenny.com/actuator/health
```

预期：内部健康 `UP`；未登录的 `/api/v1/users/me` 返回应用JSON的 `401 / AUTHENTICATION_REQUIRED`；公网 `/actuator/health` 仍由站点拒绝（当前模板404）。API出现502不能算成功；只看到 `/nginx-health` 正常也不够。

上面用 `--resolve` 验证服务器本机Nginx，同时保留域名与证书校验；不依赖服务器访问自身公网IP的回流能力。再从自己的电脑执行以下正常DNS请求，并在手机体验版/正式入口登录、读取账单和统计：

```powershell
curl.exe -sS -i --connect-timeout 3 --max-time 10 https://www.cr-chenny.com/api/v1/users/me
```

只改内部端口时，域名与443不变，**小程序 trial/release 地址、微信 request 合法域名、证书和备案信息都不用改，也无需为此重新上传小程序**。

失败时看本项目日志：

```bash
journalctl -u account-book.service -n 80 --no-pager
tail -n 50 /var/log/nginx/account-book.error.log
```

## 10. Windows 本地开发也更换端口

**当前一键启动器没有统一可配置的后端端口参数。** `Start-Dev.ps1`只有 `-UpdateBackend`；`Start-LocalBackend.ps1`只有 `-ExistingConfigurationOnly`。因此不能直接写 `Start-Dev.cmd -Port 17631`，也不能仅设置终端 `$env:SERVER_PORT` 就认为成功：`LocalBackend.psm1`重新组装子进程环境并固定写入7631。

如果只换服务器内部端口，电脑继续使用7631即可；本节只适用于也要换电脑本地监听的情况。

### 10.1 必须协调修改的位置

| 文件 | 要核对/修改的内容 |
|---|---|
| `deploy/scripts/LocalBackend.psm1` | 子进程 `SERVER_PORT`；端口占用校验；获取监听端口集合 |
| `deploy/scripts/DevStartup.psm1` | 端口扫描、Java归属/复用、旧进程退出判断、健康检查URL、启动提示 |
| `deploy/scripts/Start-Dev.ps1` | 对外错误文案中的旧端口；如要参数化须新增并传递真实参数 |
| `deploy/scripts/Start-LocalBackend.ps1` | 本地启动及错误提示；参数化时须与模块联动 |
| `account-book-miniapp/miniprogram/config/env.ts` | develop分支的 `http://127.0.0.1:7631` 改为目标端口 |
| `account-book-miniapp/miniprogram/store/session.ts` | 默认 `environmentId` 含旧地址；实际runtime也使用环境+地址隔离会话 |
| `account-book-server/src/main/resources/application.yml` | 如果要改“无环境变量时的默认端口”，更新7631回退值；仅由启动器传SERVER_PORT则无需改默认值 |
| `account-book-server/src/main/resources/application-prod.yml` | 只有连生产默认值也要统一时才改，生产env覆盖仍优先 |
| 对应测试 | 更新受影响的URL/环境标识/监听/日志断言，保留行为保护 |

不需要修改 `DB_URL` 的3306/13306，也不要把所有数字做全库盲目替换。历史执行记录中的7631保留历史事实，新操作记录另写。

### 10.2 操作顺序

1. 先确认要操作的是主目录及本项目Java进程，记录原端口和启动方式；受控停止本地Java，确认原监听释放。
2. 按上表统一修改，较长期的做法是为启动链路增加一个共享的端口参数，而不是维护多套互不相干的数字。
3. 搜索剩余引用并逐条分类为实际配置、测试、历史文档：

```powershell
Set-Location -LiteralPath 'D:/Work/Workplaces/privateWork/AAProject/MyTallyBook_Project'

```

4. 在主目录运行受影响的启动器离线测试和前端检查：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\scripts\tests\Test-LocalBackend.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\scripts\tests\Test-DevStartup.ps1
```

如果改到后端YAML默认值，另运行后端 `RuntimeConfigurationTests` / `ProductionConfigurationTests` 配置测试，并检查配置相关文档。只是切换外部环境变量，不要求为此重新编译JAR。

5. **先完成第26号手册10.1节要求的数据库隔离，再启动本地服务。** 当前本地启动器连向服务器 `account_book_dev`，它已承载正式数据；改HTTP端口不会自动隔离数据库，不能据此把本地操作当作无影响测试。

8. 回退时按此次变更前备份或逐项反向补丁恢复涉及的端口配置，再重启/重新编译。不要用 `git reset --hard` 或整库覆盖抹掉其他未提交改动。

| 重装/重新渲染Nginx | Linux安装器使用 `--backend 127.0.0.1:17631`；Windows `Install-NginxProd.ps1`没有对应透传参数，不能直接沿用默认操作 |
| 修改模板 | 活动配置在 `/etc/nginx/`；只改仓库或 `/opt/nginx/templates/` 不会自动生效。模板保留7631时，后续每次渲染必须显式传新目标 |
| 项目安装标记 | `/opt/nginx/INSTALL-MARKER`只记录上次安装，手工改端口后可能仍显示7631；运维记录需注明新端口，判断以活动配置为准 |
| 新环境文件 | `deploy/account-book.env.example`仍示例7631；用于新部署时要填目标端口，不能覆盖现有秘密配置 |
| 全项目默认端口统一 | 除源码/模板外，还要更新 `deploy/systemd/tests/`、`deploy/nginx/tests/`、`deploy/scripts/tests/` 和前后端相关断言；仅单台生产env覆盖则不必改默认合同 |

只有端口变更，不需要重建数据库、不需要轮换Pepper/AppSecret、不需要改域名证书、不需要调整业务表迁移版本。
