## 2. 本次实现

### 2.1 不可变 V1 与增量 V2

- `V1__init_schema.sql` 已恢复为开发库执行过的原始版本，工作区与 Git HEAD 内容一致。
- 新增 `V2__align_approved_design.sql`，负责：
  - 用固定值唯一单例键保证全库最多一条账本记录，同时不改动原 V1 已被外键引用的主键结构。
  - 把旧多次邀请模型改为 `used_by/used_at` 的单次邀请模型。
  - 删除 `book_entry.member_id`，统计维度统一使用 `created_by`。
  - 将 `audit_log.request_id` 扩展为 `VARCHAR(64)`。
- V2 在任何持久结构修改前检查旧账本和邀请；只要存在多个账本、非标准固定账本 ID、`used_count != 0` 或旧状态无法无损映射，就立即失败并保留旧列，等待人工确认数据迁移规则。
- 禁止通过 `flyway repair` 修改或掩盖 V1 校验和。

### 2.2 固定测试库安全门禁

数据库测试同时满足以下条件才会清理并迁移测试 schema：

1. URL 精确选择 `account_book_test`。
2. 主机和端口精确为 `127.0.0.1:13306`。
3. 用户名精确为 `account_book_test_app`。
4. `DB_TEST_RESET_ALLOWED` 精确等于 `account_book_test`。
5. 建立连接后服务端一次执行 `SELECT DATABASE(), CURRENT_USER()`；结果必须精确为 `account_book_test` 与 `account_book_test_app@127.0.0.1`。

真实测试门禁与 test harness 在开始和结束都只调用 Flyway 清理该 schema 内对象；其中没有可执行的管理员、root 或删库路径。这不改变一次性数据库初始化脚本的独立职责；管理员、root 或删库字样在本门禁上下文只允许出现在负向防护测试或历史说明中。当前唯一可执行门禁见本节与第 4 节。

### 2.3 运行配置

- 默认监听 `${SERVER_ADDRESS:127.0.0.1}:${SERVER_PORT:7631}`。
- DataSource 仅引用 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`，仓库不保存真实值。
- Hikari 最小空闲连接数为 1，最大连接数为 5，适合当前 10 人以内规模。
- Flyway 启用并在启动时校验；JPA `open-in-view=false`、`ddl-auto=validate`。
- 控制台日志格式包含 MDC `requestId`。
- 小程序 `develop` 环境请求 `http://127.0.0.1:7631`；体验版和正式版仍必须配置备案后的 HTTPS API 域名。

### 2.4 HTTP 与可观测性

- 参数类型、方法级校验和不可读 JSON 返回 `400 VALIDATION_FAILED`。
- 不支持的方法返回 `405 METHOD_NOT_ALLOWED`。
- 数据完整性和乐观锁冲突返回 `409 CONFLICT`。
- 不支持的媒体类型返回 `415 UNSUPPORTED_MEDIA_TYPE`。
- `/actuator/health` 可匿名访问；其他业务接口维持默认认证。
- 未知异常日志只记录请求 ID、HTTP 方法、安全路由模板和异常类型，不记录异常消息、请求体或认证头。
