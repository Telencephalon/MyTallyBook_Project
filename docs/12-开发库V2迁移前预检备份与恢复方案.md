数据库密码目前通过短期 root 子进程的 `MYSQL_PWD` 传入，避免命令行或磁盘持久存储，但这不等于对同机高权限进程保密；MySQL 官方不推荐环境变量密码。当前入口仅用于受控运维，不用于常驻服务或多用户共享执行环境。[MySQL 环境变量安全说明](https://dev.mysql.com/doc/refman/8.0/en/environment-variables.html)

## 3. 预检和备份的执行顺序

1. 核对服务器侧 `mysql`、`mysqldump` 均为 8.0 工具，避免使用 Windows 上现有的 MySQL 5.7 客户端。先解析 `mysql` 命令路径，并检查其同目录的可执行 `mysqldump`，再查 PATH 和服务器版本输出中已出现的 `/opt/mysql8/bin/`；实际执行使用绝对路径。版本检查后，以真实公共连接参数加 `--help` 验证参数可解析，该步骤不连接数据库。不修改 PATH、不安装软件；工具缺失或参数不支持时停止，不再索要数据库密码。
2. 对开发库和测试库分别查询 `DATABASE()`、`CURRENT_USER()`、版本和服务器 UUID；必须匹配固定库名、固定应用账号及同一实例。
3. 确认测试库没有表、视图、存储程序、触发器或事件。
4. 确认开发库恰好是原始 V1 的 11 张 InnoDB 表，且没有额外存储对象。
5. 核对 Flyway 历史只含成功的原始 V1，并与本地 V1 校验和匹配；检测 V2 残留字段，核对旧字段类型。
6. 确认账本数量不超过 1，已有账本 ID 只能是 1；旧邀请不能有消费记录或无法映射的状态。发现偏差立即停止，先明确迁移规则。
7. 记录各表行数并检查可用空间；本工具处理开发库估算大小低于 256 MiB 的情况，更大数据量先重新评估备份流程。
8. 在服务器创建独立 `/var/backups/mytallybook-dev-v2-随机后缀/` 目录，以服务器端 `mysqldump` 输出备份，记录 SHA-256。
9. 将备份恢复到空的固定测试库，检查表清单和逐表行数；以相同参数再导出测试库，要求整个 SQL 文件 SHA-256 与源备份相同。
10. 清理本轮恢复的测试表，并通过独立查询确认测试库仍可连接且为空。
11. 下载开发库备份到本地 `backup/dev-v2/时间戳/`，再次核对 SHA-256，写入非敏感结果清单。

备份使用 `--single-transaction --quick --set-gtid-purged=OFF --no-tablespaces`，不申请全局读锁；适用于已确认的 InnoDB 表。备份过程中不得有并行 DDL。脚本不会关闭其他服务来满足这个条件；正式迁移前还需确保本项目写入暂停。[MySQL mysqldump 官方说明](https://dev.mysql.com/doc/refman/8.0/en/mysqldump.html)

备份不带 `--databases`，因此不包含切换到开发库的 `USE`/建库语句。脚本会再次检查数据库切换/建库语句（含版本注释形式）以及 `account_book_dev.表名` 限定引用，避免恢复演练写回源库；Flyway 历史里的普通账号值 `account_book_dev_app` 不应被当成跨库 SQL。此检查仅用于本脚本自己生成的标准 mysqldump 文件，不是用于执行任意来源 SQL 的通用安全解析器。[MySQL SQL 备份恢复说明](https://dev.mysql.com/doc/refman/8.0/en/reloading-sql-format-dumps.html)
