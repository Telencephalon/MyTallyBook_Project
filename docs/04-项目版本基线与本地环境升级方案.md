## 3. 本次执行边界

1. 通过 NVM for Windows 安装 Node.js 24.20.0 64 位版本。
2. 通过 `nvm use 24.20.0` 将 NVM 默认激活版本切换为 Node.js 24 LTS。
3. 卸载 Node.js 13.14.0、16.20.2 和 18.20.8，NVM 中只保留 24.20.0。
4. 新建终端验证 `node` 与 `npm` 实际命中的路径和版本。
5. 将系统级 `JAVA_HOME` 设为 `D:\Work\Config\JDK\JDK\jdk21`，并用 `%JAVA_HOME%\bin` 替换系统 `Path` 中的旧 Java 8 路径。
6. 小程序固定 TypeScript 5.9.3 和 `miniprogram-api-typings` 5.2.3，并使用 npm 11.19.0 重建锁文件及依赖。
7. 本次不更改 MySQL、Ubuntu、微信开发者工具或 Spring Boot，也不删除旧 JDK 文件。

## 4. Node.js 执行命令

在具有 NVM 切换权限的 PowerShell 中执行：

```powershell
nvm install 24.20.0 64
nvm use 24.20.0
nvm current
node --version
npm --version
where.exe node
```

如果 `nvm use` 提示权限不足，应关闭当前终端，以管理员身份打开 PowerShell，仅重试：

```powershell
nvm use 24.20.0
```

## 5. JDK 21 检查标准

已安装的 JDK 21 路径为：

```text
D:\Work\Config\JDK\JDK\jdk21
```

系统级配置脚本：

```powershell
Start-Process -FilePath 'powershell.exe' `
    -Verb RunAs `
    -Wait `
    -ArgumentList '-NoProfile','-ExecutionPolicy','Bypass','-File','deploy\scripts\configure-windows-jdk21.ps1'
```

需要在新打开的 PowerShell 中同时满足：

```powershell
[Environment]::GetEnvironmentVariable('JAVA_HOME', 'Machine')
$env:JAVA_HOME
where.exe java
java -version
.\account-book-server\mvnw.cmd --version
```

验收标准：

- 系统级 `JAVA_HOME` 是 `D:\Work\Config\JDK\JDK\jdk21`。
- 系统 `Path` 首项是 `%JAVA_HOME%\bin`，且不再包含旧 Java 8 路径。
- `where.exe java` 的第一个结果位于 JDK 21 的 `bin` 目录。
- `java -version` 显示 21.0.11 LTS。
- Maven Wrapper 的 `Java version` 显示 21.0.11。

IDEA 的 Project SDK 、Maven Runner JDK 与 Windows `JAVA_HOME` 是三组独立配置；仅在 IDEA 中选择 JDK 21，不会改变 PowerShell 和 Maven Wrapper 的默认 Java。

## 6. 回退

Node.js 24 若与旧项目不兼容，需重新安装旧版本后切换：

```powershell
nvm install 16.20.2 64
nvm use 16.20.2
node --version
npm --version
```

回退时不需要卸载 Node.js 24。
