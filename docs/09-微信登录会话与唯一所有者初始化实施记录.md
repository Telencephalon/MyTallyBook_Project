## 2. HTTP 接口

所有成功响应使用统一 `ApiResponse` 外层，所有错误使用稳定错误码并返回 `requestId`。

| 方法 | 路径 | 认证 | 结果 |
|---|---|---|---|
| `POST` | `/api/v1/auth/wechat/login` | 否 | 返回三种登录状态之一 |
| `POST` | `/api/v1/auth/bootstrap` | 否 | 正确口令首次初始化后返回会话 |
| `POST` | `/api/v1/auth/logout` | 是 | 只撤销当前 Bearer Token |
| `GET` | `/api/v1/users/me` | 是 | 返回当前有效成员资料 |
| `PATCH` | `/api/v1/users/me` | 是 | 更新昵称和/或头像 |
| `GET` | `/api/v1/ledger` | 是 | 返回认证上下文中的固定账本 |
| `PATCH` / `PUT` | `/api/v1/entries/{entryId}` | 是 | 当前实现与小程序兼容的账单更新合同；必须携带 `version` |

登录成功的 `data`：

```json
{
  "state": "AUTHENTICATED",
  "token": "仅在成功响应中返回一次",
  "expiresAt": "2026-09-30T02:00:00Z"
}
```

未初始化返回 `NEED_BOOTSTRAP`，已初始化但没有有效成员关系返回 `INVITE_REQUIRED`。这两种状态均不创建用户或会话。

## 3. 初始化事务

初始化前在事务外完成请求校验、微信 code 兑换和候选 Token 生成。事务内按以下顺序执行：

1. 对 `app_config(id=1)` 执行 `SELECT ... FOR UPDATE`。
2. 已初始化时返回 `ALREADY_INITIALIZED`。
3. 未配置口令时返回 `BOOTSTRAP_NOT_CONFIGURED`。
4. 对配置值和输入值分别计算 SHA-256，再使用 `MessageDigest.isEqual` 比较固定长度摘要。
5. 创建一个用户、固定账本 `id=1`、唯一 OWNER 成员、15 个默认分类和 4 个默认资金账户。
6. 将 `app_config.initialized` 设为真并递增版本。
7. 插入会话摘要和 `SYSTEM_BOOTSTRAP` 审计后提交。

初始化成功后，数据库状态使初始化口令永久失效。即使环境变量仍存在，后续请求也会先读到 `initialized=true` 并返回 409；部署确认成功后应删除 `APP_BOOTSTRAP_KEY` 并重启服务。

## 4. 会话与安全设计

原始 Token 使用 `SecureRandom` 生成 32 字节随机值，再用 Base64URL 无填充编码。数据库只保存：

```text
lowercase_hex(HMAC-SHA256(
  key = APP_TOKEN_PEPPER,
  message = rawToken UTF-8 bytes
))
```

会话校验每次从数据库关联查询 `auth_session`、`app_user`、`ledger_member` 和 `ledger`，要求：

- Token 未撤销且未过期。
- 用户、成员关系和固定账本均为 `ACTIVE`。
- 成员角色来自数据库，不信任客户端参数或 Token 内容。

原始 Token、微信 code、`openid`、`session_key`、AppSecret、初始化口令和数据库密码均不进入日志或审计。资料更新审计只记录 `nicknameChanged`、`avatarChanged` 两个布尔值。

## 5. 资料更新三态语义

`PATCH /api/v1/users/me` 区分字段缺失和显式 `null`：

```text
{}                         -> 400 VALIDATION_FAILED
{"nickname":"家庭成员"}   -> 只更新昵称
{"avatarUrl":null}        -> 只清空头像
```

昵称出现时不得为 `null`，去除首尾空白后长度必须为 1～64；头像可传 `null` 或空字符串清除，非空值必须为不超过 512 个字符的 HTTPS URL。

## 6. 环境变量

生产运行需要在受控环境文件或 systemd 环境中提供变量，变量值不得进入 Git：

| 变量 | 用途 |
|---|---|
| `WECHAT_APP_ID` | 微信小程序 AppID |
| `WECHAT_APP_SECRET` | 微信小程序 AppSecret |
| `APP_BOOTSTRAP_KEY` | 首次初始化口令，成功后删除 |
| `APP_TOKEN_PEPPER` | 会话 HMAC 密钥，至少 32 个字符 |
| `DB_URL` | 生产 JDBC URL，默认同机 `account_book` |
| `DB_USERNAME` | 生产数据库专用账户 |
| `DB_PASSWORD` | 生产数据库密码 |

真实 MySQL 集成测试只在当前进程临时使用 `DB_TEST_URL`、`DB_TEST_USERNAME`、`DB_TEST_PASSWORD` 和 `DB_TEST_RESET_ALLOWED`，不写文件。测试不再需要或接受管理员 URL。

## 7. MySQL 8 隔离验证

测试生命周期强制执行以下门禁：

1. `DB_TEST_URL` 必须使用 `127.0.0.1:13306` SSH 隧道并精确选择 `account_book_test`。
2. `DB_TEST_USERNAME` 必须精确为专用账号 `account_book_test_app`，禁止使用 root 或开发账号。
3. 必须显式设置 `DB_TEST_RESET_ALLOWED=account_book_test`；缺失或不同值时，在建立清理器前立即停止。
4. 建立连接后服务端一次执行 `SELECT DATABASE(), CURRENT_USER()` 二次确认；结果必须精确为 `account_book_test` 与 `account_book_test_app@127.0.0.1`。
5. 测试开始和结束时仅允许 Flyway 清理该数据库中的 schema 对象；固定测试数据库本身始终保留，绝不执行 `DROP DATABASE`。
